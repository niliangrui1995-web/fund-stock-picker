## 1. 目标与范围

在“出海钱眼”现有 React/Vite 单页应用中，新增“两融”栏目。顶部导航从“研究｜方法论”扩展为“研究｜两融｜方法论”，其中“两融”位于“研究”右侧。该栏目一期仅在本机离线运行，不引入登录、账户、交易、在线数据刷新或独立网站。

栏目提供以下研究展示：

1. 主指标二选一：
   - 两市融资余额（亿元）
   - 沪深融资余额／沪深 A 股市值（%）
2. 可复选叠加指数：
   - 上证指数 000001
   - 深证综指 399106
   - 创业板指 399006
3. 时间范围：1 年、3 年、5 年、10 年、全部，以及图内缩放。
4. 数据截止日、来源、审计状态、口径与风险提示。

一期不包含：

- 网页内的数据更新按钮、实时行情、网络 API 或账号功能；
- 两融买卖、持仓、交易建议、择时信号或回测胜率；
- 对现有基金季度配置、基金检索状态、SEO 季度产物的改动；
- 将 DFCF 日更数据混入既有 verified、历史信号或正式回测资产。

## 2. 已确认的口径

### 2.1 指标名称与公式

页面指标名称固定为“沪深融资余额／沪深 A 股市值”。

    描述性比率（%） = DFCF 沪深两市融资余额 ÷ 沪深 A 股市值 × 100

分母候选构成：

    沪市主板 A 股
    + 沪市科创板 A 股（需逐日确认并剔除 CDR；无法确认则该日 N/A）
    + 深市主板 A 股
    + 深市创业板 A 股
    + 历史中小板 A 股

排除 B 股、北交所、基金、ETF、REIT、债券及无法确认的 CDR。

### 2.2 必须固定披露的限制

DFCF 市场级融资余额的标的范围可能包含非 A 股证券，例如 ETF、基金、存托凭证或债券。因此该比率可以做到交易所范围与日期严格对应，但并非资产类别完全一致的估值指标。

页面在指标说明、来源信息和提示框中固定披露：

> 分子可能包含非 A 股融资标的；本指标仅作描述性比例展示，不代表资产类别完全匹配的估值口径。

融资余额的下降或上升仅反映去杠杆压力代理或杠杆使用变化，不能据此证明强制平仓、爆仓、市场底部或必然反弹。

## 4. 数据生产与发布流程

### 4.1 输入

1. 两融余额：审计通过的 DFCF dfcf_margin_balances.csv 与 dfcf_margin_audit.json。
2. 沪深市值：独立构建的上交所、深交所官方逐日分类市值快照及其原始响应、解析和审计结果。
3. 指数收盘价：本地 TDX sh000001.day、sz399106.day、sz399006.day 解析后的只读快照。

市值快照的构建必须与 DFCF 日更链分离。它不得改写 DFCF 四个日更产物、verified_margin_balances.csv、历史信号、回测工作簿或其他受控历史资产。

### 4.2 市值快照准入

每个日期至少保留以下可审计字段：

    date
    sh_main_a_yi
    sh_star_a_yi
    sh_b_yi
    sh_a_total_yi
    sz_main_a_yi
    sz_chinext_a_yi
    sz_legacy_sme_a_yi
    sz_b_yi
    sz_a_total_yi
    sh_sz_a_total_yi
    source_url
    source_schema_version
    raw_sha256
    parsed_sha256
    scope_identity_status
    date_match_status
    reporting_eligible

金额以 Decimal 与明确单位计算。按上交所、深交所接口及板块分类变更保留版本化映射。任一日期出现以下情况时，比例数据为 N/A：

- 原始响应、解析或输出哈希不符；
- 一方交易所缺失、分类不明、非正市值；
- 市值身份式或范围校验失败；
- 科创板或深市分类无法确认已排除 CDR；
- 与 DFCF 日期不能精确匹配。

不得用全 A（含北交所）市值、周末值、前值、估算值或移位日期替代。现有乐咕乐股全 A 市值序列不进入本功能。

### 4.3 发布包生成

构建器在独立暂存目录生成两个文件：

    leverage-dashboard.json
    leverage-dashboard.manifest.json

验证通过后，才原子替换到：

    D:\vcp_hunter\基金持仓\public\data\

若本次构建失败，前端保留上一份完整通过校验的发布包，并显示其真实数据截止日；不得把失败构建、部分新数据或旧值伪装为当前数据。

### 4.4 发布包最小契约

leverage-dashboard.json 至少包含：

    {
      "schema_version": "1",
      "generated_at_beijing": "ISO-8601 时间",
      "records": [
        {
          "date": "YYYY-MM-DD",
          "sh_margin_yi": 0,
          "sz_margin_yi": 0,
          "total_margin_yi": 0,
          "sh_a_market_cap_yi": 0,
          "sz_a_market_cap_yi": 0,
          "ratio_pct": 0,
          "index_000001_close": 0,
          "index_399106_close": 0,
          "index_399006_close": 0
        }
      ],
      "provenance": {}
    }

无法使用的数值使用 null，不能写入 0、前值或估算值。records 按日期升序且日期唯一。

leverage-dashboard.manifest.json 至少包含：

- 发布包 SHA-256、模式版本和生成北京时间；
- 每个输入序列的首末日、行数、输入 SHA-256；
- DFCF 的 dfcf_only=true、exchange_requests=0 审计标记；
- 市值范围校验、日期匹配、reporting_eligible 状态；
- 每个指数的来源、首末日和静态化 SHA-256；
- 明确的来源文字与披露文本。

DFCF 的 exchange_requests=0 仅描述融资余额输入链的 DFCF-only 审计结果；官方沪深市值快照是独立链路，其访问、原始响应和审计不得计入或改写 DFCF 日更审计。

## 5. 日期、缺失值与归一化规则

1. 融资余额主序列使用 DFCF 沪深共同日期。
2. 比例仅使用融资余额与合格沪深市值的精确同日交集。
3. 每条指数仅在它与当前主指标均可用的日期绘制；无数据的日期断线，不前填、不后填、不移日。
4. 选择一个或多个指数时，全部“已选且在所选范围内至少有一条可用收盘价”的指数使用同一基期：当前主指标和这些可用指数在所选时间范围内同时可用的最早日期，归一化为 100。
5. 改变主指标、预设时间范围或手动起止日期时，重新确定共同基期；仅拖动图内 dataZoom 不重设基期。
6. 某一已选指数在所选范围内完全缺失时，只将该指数标记为 N/A，不阻断主指标或其他可用指数；某一指数仅部分缺失时断线。若全部已选指数均无可用收盘价，给出 N/A 原因并保持主指标可用。

提示框显示当日主指标原值、各指数原始收盘点位、归一化值及共同基期日期。

## 6. 前端结构与导航

现有项目为 React 19 + TypeScript + Vite 6 单页应用，采用锚点滚动而非 React Router。实现保持这一模式：

    App.tsx
      ├── 研究 section
      ├── 两融 section（新增，id="leverage"）
      └── 方法论 section

顶部导航状态扩展为：

    "research" | "leverage" | "methodology"

“两融”按钮位于“研究”之后，点击后平滑滚到 #leverage。窄屏不再完全隐藏导航，而是保留可横向滚动或等宽压缩的三项导航；不得出现桌面有“两融”、移动端无法到达该栏目。

建议的最小组件边界：

| 单元 | 职责 |
| --- | --- |
| LeverageDashboard | 读取发布包、管理加载与错误状态、组合控制区与图表 |
| LeverageControls | 主指标、指数复选、时间范围与日期范围 |
| LeverageChart | ECharts 选项、同步轴、提示框、缩放与归一化 |
| LeverageSummary | 当前指标、沪深拆分、数据截止日与审计状态 |

图表库使用 npm 依赖随 Vite 打包到本地资产，不使用 CDN，以符合现有 script-src self 与离线需求。

发布包以相对路径读取，适配子路径部署；加载在用户首次进入“两融”栏目时触发，避免影响既有“研究”首屏。

## 7. 页面布局与交互

布局沿用参考站的深色顶部栏、浅色内容卡片、紧凑研究信息层级和克制强调色，不复制其具体实现。

### 7.1 控制区

- 主指标：分段单选，默认“两市融资余额（亿元）”。
- 指数：三个复选项，初始均选中；用户可取消任意指数。
- 时间：默认近 10 年，可切换 1/3/5/10 年、全部和手动日期范围。

### 7.2 摘要卡

摘要区至少显示：

- 当前主指标及相对前一共同日变化；
- 沪市、深市融资余额；
- 数据共同截止日；
- DFCF 审计状态与厂商口径标签。

切换到比例模式后，首张卡切换为描述性比率及其变化；融资余额拆分仍保留为背景信息，但不与百分比混用单位。

### 7.3 主图

- 左轴只绘制当前主指标，单位随模式明确切换为亿元或百分比。
- 右轴只绘制已选指数的归一化值，明确标注“共同基期 = 100”。
- 原始指数点位不与主指标共用坐标轴，仅在提示框显示。
- 图例可交互开关；缩放和十字指针在各序列间同步。
- 指数不选时隐藏右轴和指数图例。

### 7.4 侧栏与披露

图表旁显示数据状态、可用日期范围、来源、审计摘要和阅读提示。图表下方固定显示描述性比率的资产范围差异。来源包括：

- DFCF：Choice 厂商口径，未经交易所复核；
- TDX：本地当前数据，非交易所官方统计；
- 沪深市值快照：官方日度来源、实际快照截止日与校验状态。

## 8. 失败处理

| 情况 | 页面行为 |
| --- | --- |
| 发布包或 manifest 请求失败 | 两融模块显示阻断卡，不显示图表或伪造旧值 |
| JSON schema、哈希或审计摘要不一致 | 阻断模块，展示“发布包校验失败”及可辨识原因 |
| DFCF 审计失败 | 阻断整个两融图表 |
| 市值快照未通过或比例缺失 | 保留融资余额模式；比例选项禁用并显示 N/A 原因 |
| 单个指数缺失 | 仅禁用该指数或显示断线；其他指数和主指标继续可用 |
| 新发布构建失败 | 网页保留上一份完整审计包，并显著显示其实际截止日 |

所有失败信息、提示、口径与告警使用中文；代码、文件名、字段名、URL 和必要枚举保留原文。

## 9. 验收标准

### 9.1 数据侧

- DFCF 输入审计通过，哈希与实际文件一致；
- 市值原始响应、解析表、输出表均可复核 SHA-256；
- 日期唯一、升序、金额非负且单位一致；
- 比例按 Decimal 重算一致；
- 比例只使用精确同日交集，缺失不补值；
- 全量历史覆盖预检通过后才开放比例模式；
- 发布包与 manifest 的输入范围、哈希、首末日和行数一致。

### 9.2 前端侧

- npm run build 成功；
- 浏览器离线运行时不请求 CDN、交易所、DFCF、TDX 或其他网络数据；
- 主指标切换后坐标轴、摘要和提示框单位一致；
- 三指数单选、多选、取消选择和缺失处理正确；
- 归一化共同基期规则正确，dataZoom 不暗中重基；
- 桌面宽度与窄屏均能访问“两融”导航和全部控制项；
- 截图 QA 覆盖默认余额、比例可用、比例不可用、单指数缺失与数据包失败状态。

## 10. 实施顺序

1. 在数据生产端建立官方沪深市值全量快照与审计预检。
2. 构建并验证两融发布包和 manifest，先在本机静态服务器中检查。
3. 在“基金持仓”前端增加导航、独立数据加载、图表与披露模块。
4. 完成数据、前端、离线和截图验收。
5. 用户确认测试结果后，再按项目备份规则提交并推送相应仓库。

## 11. 明确边界

- 不覆盖或改写 DFCF 日更四个受控产物、正式回测、历史信号或基金季度发布资产。
- 不把本页面的 DFCF 日更结果并入既有正式回测样本或胜率。
- 不把厂商行情、描述性比例或视觉相关性升级为因果、投资结论或交易指令。
