# 多股票组合研究升级设计

日期：2026-08-28

状态：设计已确认，待规格审阅；尚未进入实施

功能归属：D:\vcp_hunter\基金持仓

## 1. 目标与范围

在“出海钱眼”现有“研究”页面内增加组合研究工作台。用户可建立并保存多个命名股票组合，每个组合含 1–10 只海外股票；页面据此返回当前季度已采集的公开股票持仓明细中、持有任一已选股票的基金，并按基金对该组合的“总估算经济暴露”降序排列。

一期同时提供：

1. 当前浏览器内的命名组合新建、编辑、切换、重命名、另存为与删除；
2. 场外基金、场内 ETF / LOF 两个互斥结果视图；
3. 每只基金对每只已选股票的直接持仓、已识别杠杆 ETP 间接估算与合计；
4. 结果页内的“融资余额 / 指数”轻量市场环境摘要，并跳转既有完整两融看板；
5. 数据季度、来源、估算口径、覆盖缺口与非投资建议提示。

一期不包含：

- 登录、云同步、跨浏览器恢复、分享链接、协作或账户体系；
- 真实券商持仓导入、基金实时仓位、盘中数据刷新或交易功能；
- 基金历史季度变化对比、收益预测、选股推荐、回测或因果判断；
- 新的两融数据生产链路、将两融变化归因到所选股票，或改写现有完整两融看板；
- 对当前工作区无关的 `dist-old-backup/`、`optimization-report.md`、`scripts/split_fund_holdings.mjs` 的处理。

## 3. 用户流程与页面结构

### 3.1 组合工作台

“研究”页顶部保留现有导航与单股票检索能力，新增紧凑的组合工作台：

1. 显示当前组合名称、数据季度、已选股票数和“保存在当前浏览器”说明；
2. 搜索并添加股票，以可移除的代码标签显示；重复添加被阻止，达到 10 只后禁用继续添加并说明原因；
3. 提供“保存更改”“另存为”“重命名”“切换组合”“删除”操作；
4. 未保存的编辑是草稿。切换、删除或离开存在未保存草稿时要求用户明确选择保存、放弃或取消；
5. 没有选股时保留现有研究页的发现/搜索入口，不显示伪造的空结果。

单股票搜索和既有深链继续可用：它们在组合层中等价于仅含该股票的临时研究状态，不要求用户先命名或保存组合。

### 3.2 结果工作面

组合工作台下方展示两个页签：

- 场外基金：所有非交易所交易的基金，包括 ETF 联接基金；
- 场内 ETF / LOF：所有交易所交易产品。

每个基金家族在一个组合中只进入一个页签。结果行包含基金名称/代码、可展开的既有持仓详情入口、各只已选股票的贡献标签、直接合计、间接估算合计和总估算经济暴露。默认按总估算经济暴露降序；大结果集按页或“加载更多”渐进呈现，但排序基于完整命中集而非当前可见页。

总估算经济暴露的解释固定置于排序附近：它是公开披露期末、当前已采集持仓明细的方向性穿透估算，不等同于基金直接持有正股，也不是实时持仓或投资建议。页面固定显示“未出现不代表未持有”，不得把未命中结果解释为基金完整组合中不存在该股票。

### 3.3 市场环境摘要

结果面右侧（窄屏移至结果后）显示“融资余额 / 指数”轻量卡片。该卡片以既有两融发布包最近 20 个共同可用交易日为区间（不足 20 日则使用全部可用共同区间），将融资余额和上证指数 `000001` 的起点各归一为 100，展示两者区间变化及“融资余额变化减指数变化”的描述性差值。卡片同时显示实际起止日期和“市场环境”标签；不可把它描述为所选股票或基金结果的原因。基金结果可用后才懒加载该摘要，且摘要不得导入 ECharts 图表代码。点击按钮仍进入现有完整两融看板，不复制或替换原有图表、区间与指数控制。

## 4. 统计口径、去重与排序

### 4.1 定义

- `fundFamilyKey`：同一基金的 A/C 等份额归并后的基金家族键。页面显示一个基金家族行，而非把份额逐条相加。
- 直接边：基金家族对一只已选正股的披露持仓。
- 间接边：基金家族持有的、已被映射到该正股的杠杆 ETF / ETP / ETN 产品。
- 原始杠杆产品占净值：基金对该产品的 `ratioPercent`，只作来源展示，绝不再进入组合合计。

### 4.2 计算公式

对基金家族 `f` 与已选股票集合 `S`：

    直接暴露(f) = Σ directRatioPercent(f, s)，s ∈ S
    间接估算(f) = Σ estimatedRatioPercent(f, s, source)，s ∈ S
    总估算经济暴露(f) = 直接暴露(f) + 间接估算(f)

其中：

    estimatedRatioPercent = 杠杆产品原占净值 ratioPercent × leverageMultiple

只有 `leverageMultiple` 为有限正数、`estimatedRatioPercent` 为有限数值、且该产品已具备正股映射时，间接边才可进入数值合计。当前生成器已排除 Short/Bear/Inverse/反向产品；组合生成端和前端仍须双重校验，不允许负数、零、空倍率或无法映射产品被悄然写成 0%。

直接持有与合格间接持有是不同资产路径：同一基金对同一正股同时具有两者时，两者可相加为总估算经济暴露，但结果行必须分列显示。

### 4.3 去重规则

1. 直接边以 `(fundFamilyKey, targetCode)` 去重；同一正股的不同份额采用现有基金家族代表规则，不把 A/C 等份额相加。
2. 间接边以 `(fundFamilyKey, targetCode, sourceCode)` 去重；同一产品的不同份额只保留一个代表记录，不重复相加。
3. 同一基金家族通过不同 `sourceCode` 持有多个、且均映射同一正股的杠杆产品时，保留各产品明细并将其估算值相加。
4. 未映射、未解析或不合格的间接产品不进入数值合计，并显示“已映射估算覆盖”限制；页面不得把这类缺口标成 0% 或宣称覆盖完整。

### 4.4 排序、入选和分类

基金家族只要至少有一条正的直接边或合格间接边，即进入结果。排序键固定为：

    totalEstimatedExposure DESC
    directExposure DESC
    fundCode ASC

分类由全量基金 profile 的交易所属性一次确定：`isOnExchangeFund = true` 进入“场内 ETF / LOF”，其余进入“场外基金”。该规则使两个页签互斥且完整，ETF 联接基金归入场外基金。

## 5. 全量组合索引与发布契约

### 5.1 现有约束

当前 `fund-stock-index-<quarter>.json` 的 `topByRatio`、`topOnExchangeByRatio` 和 `topIndirectExposureByRatio` 均为展示前 10 名；`fund-holdings-<quarter>.json` 亦只为既有可见基金生成前十持仓详情。因此它们只能服务现有单股票展示，不能用作多股票全量相加或排序的数据源。

本功能中的“全量组合索引”仅表示：对当前季度已采集的公开股票持仓明细行（源行在个别基金中可超过前十名），在网页展示截断前完整参与组合计算。它不代表基金完整投资组合、实时仓位或“未命中即未持有”。基金详情卡片仍最多展示 10 条持仓，不能把详情显示上限混同为组合计算覆盖范围。

组合功能必须在 `scripts/build_fund_stock_index.py` 的截断前全量记录上生成独立发布产物，不得通过浏览器拼接这些 `top*` 数组。这样可避免遗漏“某只股票单项排名靠后、但多只股票合计暴露较高”的基金。

### 5.2 新发布产物

每个基金持仓季度生成版本化的组合索引 manifest 和按股票分片的数据文件，建议路径为：

    public/data/fund-portfolio-index-<quarter>.manifest.json
    public/data/fund-portfolio-index-<quarter>/<release-id>/<canonical-stock-code>.json

manifest 至少包含：

- `schemaVersion`、不可变 `releaseId`、`report`、`cutoffDate`、`generatedAt`、构建器版本；
- 每只可选股票的分片相对路径、SHA-256、直接边数和合格间接边数；
- 基金家族归并规则版本、场内/场外分类版本；
- 输入持仓总行数、可发布状态、数据来源与披露文本；
- 全局间接暴露覆盖摘要：已映射行数、未映射/排除行数、审计文件路径与固定的“未映射不按 0% 计入”提示。

每个股票分片至少包含：

- 当前正股的代码与名称；
- 以 `fundFamilyKey` 为键的规范基金家族 profile（展示代码/名称、基金类型、合并份额代码、交易所属性）；
- 直接边：`fundFamilyKey`、`targetCode`、`targetName`、直接 `ratioPercent`；
- 合格间接边：`fundFamilyKey`、`sourceCode`、`sourceName`、`targetCode`、`targetName`、`leverageMultiple`、`estimatedRatioPercent`、`matchReason`；
- 分片 schema、季度、生成时间、完整性字段。

未映射产品没有可靠的目标股票代码，不能伪装成某一股票分片的 0 值或缺口；它们只在 manifest 的全局覆盖摘要和现有间接暴露审计文件中披露。

生成器先在新的不可变 `releaseId` 目录完整写入、哈希并验证所有分片，最后才原子替换季度 manifest。分片使浏览器最多按当前选择的 10 只股票加载必要数据，而不是在研究页首屏下载全部未截断持仓边；manifest 引用的 `releaseId` 使缓存客户端不会读到新旧混合包。所有请求仍为同源相对静态文件，不引入第三方接口。

### 5.3 数据生成校验

生成器在发布前必须校验：

1. 每条直接和间接边具有有效基金家族键、目标代码和有限数值；
2. 直接/间接去重键与代表份额规则一致；
3. 合格间接边的 `estimatedRatioPercent` 可按 `ratioPercent × leverageMultiple` 复算；
4. 不合格间接边不混入合计，且覆盖摘要与原始审计行一致；
5. 每个基金家族只具备一个互斥的结果视图分类；
6. manifest 中的行数、哈希、分片列表、季度和数据截止信息与实际文件一致。

任一分片或 manifest 校验失败时，不发布部分新组合索引；前端只接受完整且季度一致的发布包。

## 6. 前端组件边界与数据流

现有 `src/App.tsx` 与 `src/styles.css` 已高度集中。本功能采用有针对性的拆分，不进行与此无关的重构。

| 单元 | 职责 |
| --- | --- |
| `src/portfolio/types.ts` | 组合、基金 profile、直接/间接边、聚合结果和存储 schema 的类型。 |
| `src/portfolio/portfolioStorage.ts` | localStorage 读写、schema 校验、迁移与存储失败处理。 |
| `src/portfolio/portfolioIndex.ts` | manifest/分片请求、结构校验、内存缓存、取消过期请求。 |
| `src/portfolio/aggregatePortfolioResults.ts` | 纯函数：去重、直接与间接累计、覆盖标记、互斥分类和稳定排序。 |
| `src/portfolio/usePortfolioResearch.ts` | 活动组合、草稿、加载状态及聚合结果的 React 状态协调。 |
| `src/portfolio/PortfolioWorkbench.tsx` | 组合编辑、保存、结果页签、基金行和空/错误状态。 |
| `src/leverage/` 的轻量摘要组件 | 在基金结果可用后懒加载既有两融发布包的摘要并提供进入完整看板的入口；不导入 ECharts，不重算两融数据。 |
| `src/App.tsx` | 保留路由/导航、单股票兼容入口和既有基金详情交互，仅负责挂载新工作台。 |

数据流为：季度搜索索引选择股票 → 加载对应组合索引 manifest/分片 → 纯聚合函数得到完整命中集 → 按互斥视图和稳定排序渲染。切换或删除股票时，应取消失效请求并忽略迟到响应；已加载分片在当前页面会话中缓存。

## 7. 本地保存与隐私

组合状态使用版本化键 `chuhaiqianyan.portfolio-baskets.v1` 保存。每项至少含：

    id
    name
    stockCodes
    createdAt
    updatedAt

根对象记录 `schemaVersion` 与 `activeBasketId`。名称去除首尾空格后不能为空，最长 40 个字符；同名保存须由用户改名或明确覆盖，避免难以区分。组合内股票代码必须是当前可搜索索引中的规范代码，最多 10 个且无重复。

本地存储只保存上述组合元数据，不保存基金持仓、两融数据或用户身份信息。读取到损坏、过期或非法记录时，隔离该记录并以可恢复提示启动空草稿；不得清理同一浏览器 origin 下的其他业务数据。浏览器禁用、额度耗尽或写入失败时，页面保持当前会话研究可用，但明确提示“无法保存到本机”，并不假装已保存。

## 8. 错误、披露与可访问性

| 情况 | 页面行为 |
| --- | --- |
| 未选股票 | 保留研究发现入口，提示可建立或打开组合。 |
| 重复或第 11 只股票 | 阻止加入并给出具体原因。 |
| manifest/分片请求或校验失败 | 阻断组合结果，不显示旧值、部分值或伪造 0 值；保留重试入口。 |
| 单一股票分片不可用 | 阻断当前组合结果并指出不可用股票；不得以少选股票的部分合计冒充当前组合结果，提供重试与移除该股票后重新计算的入口。 |
| 未映射间接产品 | 不写入数值合计，显示覆盖限制与来源说明。 |
| 某个页签无命中 | 显示该分类无匹配基金，不影响另一个页签。 |
| 两融摘要不可用 | 不阻断基金研究；摘要显示不可用状态，完整看板入口仍遵循其自身数据校验。 |

组合编辑、页签、排序、基金详情和两融入口必须支持键盘操作、可见焦点和语义化名称。金额/涨跌/覆盖状态不能仅依赖颜色；移动端操作目标不小于 24×24 CSS px。结果附近固定披露数据季度、来源、当前“已采集公开股票持仓明细”覆盖边界、`未出现不代表未持有`、基金详情最多展示 10 条、计算公式、间接估算边界和非投资建议，避免把披露期末持仓理解为实时仓位。

## 9. 验收标准

### 9.1 数据与计算

- 全量组合结果不读取或依赖 `topByRatio`、`topOnExchangeByRatio`、`topIndirectExposureByRatio`；
- 选择 `00700` 时，可命中现有前 10 名外的合格基金，证明未被展示截断限制；
- 直接持仓、仅合格间接、直接与间接混合、多只股票累计和稳定并列排序均正确；
- A/C 等份额不重复相加；不同杠杆产品 `sourceCode` 映射同一正股时正确相加；
- Q2 回归样例：选择 `000660` 与 `005930` 时，已审计基金家族的两条间接估算合计为 `9.74% + 3.80% = 13.54%`，不得因两份额重复成 `27.08%`；
- 负、零、空杠杆倍率和未映射记录不进入数值总和，并显示覆盖缺口；
- 每个基金家族在两个结果视图中至多出现一次，ETF 联接归入场外视图。

### 9.2 交互与持久化

- 可创建、保存、切换、重命名、另存为、删除多个命名组合；刷新页面后已保存组合和活动组合可恢复；
- 重复股票、超过 10 只、无效名称、未保存草稿切换和 localStorage 不可用均有可理解的行为；
- 单股票搜索、既有深链、基金详情展开、场外/场内结果视图及完整两融看板不回归；
- 结果页可在桌面、390px 和 320px 窄屏下完成添加、删除、页签切换和基金详情操作，不发生横向内容溢出。

### 9.3 工程质量

- 组合聚合和本地存储具有独立单元测试；数据生成器具有发布前契约测试；
- 生产构建、现有研究页 QA、现有两融测试与新增组合场景 QA 全部通过；
- 研究页首屏不下载全部未截断组合边；非首屏两融完整图表仍按既有懒加载策略运行；
- 不引入 CDN、第三方数据请求或账号依赖；
- WCAG 2.2 AA 相关的键盘、焦点、对比度和非颜色提示验收通过。

## 10. 高层实施顺序

1. 在现有持仓构建链中，于展示截断前生成、校验并发布全量组合索引 manifest/分片；
2. 为组合存储、分片加载与纯聚合函数建立测试，再实现组件；
3. 在研究页挂载工作台，接入两个互斥结果视图与既有基金详情；
4. 接入不阻断的两融摘要入口与披露文案；
5. 完成数据、交互、可访问性、性能、桌面/移动端及既有页面回归验证；
6. 用户确认测试结果后，再按项目备份规则处理提交与推送。
