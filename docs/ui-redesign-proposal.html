出海钱眼 — 全新 UI 重设计方案

基金持仓穿透工具 · 2026年9月 · 版本 2.0

一、设计理念

当前"出海钱眼"已具备完善的基金持仓穿透功能，但界面信息密度高、视觉层次不够清晰。本次重设计聚焦三个核心目标：

信息清晰

通过统一的字体层级、间距节奏和色彩语义，让用户一眼识别关键数据——基金代码、占比、申赎状态。

操作高效

搜索→选择→查看持仓 三步走，每步提供即时反馈；键盘可全程操作，移动端触控友好。

视觉舒适

扁平化设计、白色为主背景、蓝色品牌色统一渗透；不使用渐变、阴影和装饰性效果。

三、研究页（基金穿透）布局方案

3.1 当前问题

  • 信息层级混乱 — 搜索区、AI 热点、热门标的、持仓表四个区域平铺，缺少视觉优先级
  • 折叠隐藏关键入口 — 热点和热门标的被包裹在 <details> 里，默认收起，用户不易发现
  • 基金表格密度过高 — 列过多（基金名称、代码、类型、占比、市值、持股数、申购、赎回、起购、限购），桌面端拥挤
  • 场景切换不明确 — "场外/场内/间接"切换器位置不突出

3.2 改进方案

页面结构（自上而下）

  1. 顶部导航栏（48px 高） — 深蓝色背景，品牌名 + 四个页面切换 + 右侧季度和数据范围标签。导航项使用 Pill 样式，激活态填充蓝色背景
  2. 标题区 — "股票找基金" + 季度信息 + 右侧"数据口径"链接
  3. 搜索框（44px 高） — 胶囊形搜索框，浅灰背景，内置图标 + 输入区 + 主按钮"查看基金"。搜索建议下拉含股票 logo + 代码 + 基金数 + 市场标签
  4. AI 热点卡片行 — 水平排列 3-5 张卡片，每张含：股票 logo 圆 + 代码 + 产业链标签 + 基金数 + "查看 →"。活跃卡片浅蓝底，非活跃白底。超过 5 张时末尾显示"更多热点"入口
  5. 选中标的标题 + 场景切换 — "NVDA · 英伟达 · 美股·NASDAQ" + 三个 Pill 切换器（场外基金/场内基金/间接暴露）
  6. 基金持仓表 — 精简列为 7 列：# / 基金名称+代码 / 类型 / 占净值+进度条 / 市值 / 申购 / 赎回。斑马纹行，悬停高亮
  7. 热门标的区 — 横排卡片网格（4-6 张），每张含 logo + 名称+代码 + 市场+基金数 + 最大占比。上方有市场筛选 Pill（美股/港股/日股/韩股/其他）
  8. 免责声明 — 浅灰底横条

关键交互改进

  • 热点和热门默认展开 — 不再使用 <details> 折叠，AI 热点和热门标的始终可见
  • 搜索即时反馈 — 输入时显示下拉建议，每项含 logo 缩略、市场标签和基金数，键盘 ↑↓ 可选
  • 持仓表行点击 — 点击基金行直接弹出持仓明细弹窗（hover 卡片在桌面端保留，移动端用弹窗替代）
  • 场景切换器视觉强化 — 三个 Pill 并排，激活态浅蓝底+蓝边框，非激活白底灰边框
实现建议： 将 research-discovery 的 <details> 改为 <section>，research-data-overview 同理。AI 热点区的 ai-hotspot-section.is-collapsed 逻辑保留，但默认不折叠。搜索区从 grid-template-columns: minmax(0, 1.8fr) minmax(280px, 1fr) 改为单列全宽。

四、两融 / 交易集中度看板布局方案

4.1 当前问题

  • 缺少关键指标卡 — 用户进入页面后无法快速获取当前余额、变化等摘要数据
  • 控件分散 — 视图切换（余额/比例）、日期选择、指数叠加分散在不同位置
  • 数据表与图表割裂 — 图表和数据表之间缺少联动视觉提示

4.2 改进方案

页面结构（自上而下）

  1. 顶部导航栏 — 同研究页
  2. 标题区 — "两融数据看板" + 数据范围说明（"融资余额完整范围：2011-08-03 起 · 截至 XXXX"）
  3. 指标卡网格（4 张） — 等宽排列：①融资余额（亿元 + 日变化）②融资/市值比（% + 口径标签）③上证指数（点 + 日变化）④数据记录数（条 + SHA-256 校验标签）。活跃指标卡浅蓝底
  4. 控件栏 — 左侧视图切换 Pill（余额/比例/数据说明）+ 右侧日期选择器和指数叠加下拉
  5. 图表区 — 占满宽度的 ECharts 图表，底部含 dataZoom 拖拽条，图表内有 hover 提示框
  6. 逐日数据表 — 图表下方紧凑表格，列：日期 / 融资余额 / 上证指数 / 融资市值比 / 分母来源。右侧有"导出 CSV"按钮
  7. 免责声明 — 浅灰底横条，说明数据口径和限制

交易集中度看板

布局结构与两融看板一致，指标卡替换为：①总成交额 ②集中度指标 ③标的数量 ④数据日期。图表区显示成交额集中度走势。

5.3 基金行卡片

每行基金持仓的卡片化呈现，替代当前纯表格行：

  • 左侧：排名圆形（浅蓝底 + 蓝字）+ 基金名称（14px/500）+ 代码/类型（12px/400）+ 申赎徽章
  • 右侧：占净值百分比（16px/500 蓝色）+ 进度条（6px 高浅蓝底 + 蓝色填充）+ 市值/股数（12px/400）
  • 整行：白色背景 + 0.5px 灰色边框 + 12px 圆角，悬停时边框变蓝
  • 点击：展开持仓明细弹窗

5.4 搜索框

  • 形态：胶囊形（border-radius: 22px），浅灰背景
  • 组成：搜索图标 + 输入区 + 清除按钮 + 主按钮"查看基金"
  • 建议下拉：每项含股票 logo（28px 圆形）+ 名称 + 代码 + 市场标签 + 基金数
  • 键盘：↑↓ 选择建议项，Enter 确认，Esc 关闭下拉

5.5 弹窗（Modal）

  • 触发：点击基金行 / 点击"查看持仓明细"
  • 尺寸：宽 min(880px, 100%)，高 max 88dvh
  • 头部：标题 + 基金代码/类型 + 关闭按钮
  • 内容：持仓列表，每行含排名 + 股票名称/代码 + 占比 + 进度条，查询标的行高亮
  • 背景：半透明遮罩 rgba(15,23,42,0.44)
  • 动画：opacity + scale 淡入，0.25s 过渡
  • 键盘：Esc 关闭，Tab 焦点循环

六、顶部导航栏重设计

当前问题

  • 高度偏高 — 70px min-height 在信息密集的金融工具中偏浪费
  • 导航项间距过大 — 30px padding 使导航项之间显得稀疏
  • 激活态指示器 — 底部蓝色条 + 光晕效果偏重
  • 右侧 meta 标签 — 带边框 + 背景，视觉噪音偏大

改进方案

  • 高度降至 48px — 更紧凑，为内容区留出更多空间
  • 导航项改为 Pill 样式 — 激活态使用 4px 圆角的蓝色填充矩形，非激活态纯文字灰色
  • 品牌名简化 — "出海钱眼" 白色 500 字重，副标题"基金持仓穿透" 浅灰色 400 字重
  • 右侧 meta 简化 — 季度标签和数据范围标签使用半透明白色圆角矩形（无边框）
  • 导航项间距 — 从 30px 降至 12px padding
  • 去掉光晕 — 激活态指示器使用纯色背景，不使用 box-shadow
CSS 变更点： .topbar 的 min-height 从 70px 改为 48px；.topbar-nav a 的 padding 从 0 30px 改为 6px 12px，激活态用 background: var(--blue-400) + border-radius: 4px 替代底部条；.topbar-meta span 去掉 border，保留 background: rgba(255,255,255,0.08) + border-radius: 4px。

七、响应式设计

桌面端 (≥1024px)

12 列网格，搜索区全宽单列。AI 热点卡片 5 列横排。基金持仓表 7 列完整显示。热门标的 4-6 列网格。内容区 max-width: 1280px。

平板端 (768-1023px)

搜索区全宽。AI 热点卡片 3 列。基金持仓表隐藏"类型"和"市值"列，改为可展开行内详情。热门标的 3 列。导航项间距压缩。

移动端 (≤767px)

导航栏可横向滚动。搜索框全宽。AI 热点卡片 1.5 列（横向滚动）。基金持仓表改为卡片列表（基金行卡片）。热门标的单列。hover 弹窗改为底部 sheet。

最小屏 (≤375px)

所有内容单列堆叠。导航横向滚动 + 触摸滑动。指标卡 2×2 网格。图表区全宽可缩放。

九、质量保障

  • 无障碍 — 保持现有 ARIA 标签和键盘导航；确保新组件有正确的 role 和 aria-label
  • 性能 — 保持懒加载策略（两融/集中度看板按需加载）；CSS 不使用渐变和阴影，减少渲染开销
  • 测试 — 复用现有 vitest 和 node --test 测试套件；新增组件视觉回归测试
  • 浏览器验收 — 使用 Playwright 桌面端 1440×1024 和移动端 390×844 截图对比
  • 构建检查 — npx tsc --noEmit + npx vite build 通过
本设计方案基于"出海钱眼"项目现有功能（React 19 + TypeScript + Vite 6 + ECharts + lucide-react）， 不引入新的前端框架或设计系统库。所有设计令牌、组件和布局均可通过修改现有 CSS 变量和组件实现。 方案中的 mockup 为概念性可视化，实际数据标签以 config/fund-quarter.json 派生的当前季度数据为准。
